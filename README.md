# zz

一个极简的文件打包/解包小工具,归档内容用哈夫曼编码压缩,无任何第三方依赖。

## 用法

```
zz [option] <in_path> <out_path>

  -p   把文件或目录打包成一个 .zz 归档
  -u   把 .zz 归档解包到指定目录
```

## 示例

```bash
# 打包一个目录
$ ./zz -p ./mydir mydir.zz

# 打包单个文件
$ ./zz -p ./a.txt a.zz

# 解包
$ ./zz -u mydir.zz ./out
```

## 编译

```bash
gcc -std=c11 -Wall -Wextra -O2 -o zz zz.c huffman.c
```

## 原理

* 打包时先在内存里拼出完整的归档数据,再用哈夫曼编码整块压缩后写盘;解包时先整块解压,再按记录顺序写文件;
* 每条记录:一条 8KB 的头(4096 字节路径 + 文件大小 + atime + mtime + 权限位 + uid/gid + 补零),后面跟文件内容,内容按 512 字节对齐,不足 512 字节的部分用 `\0` 补齐;
* 目录顺序先于其子项写入,解包时按顺序重建目录结构。

## 格式

`.zz` 文件就是一个哈夫曼编码块,自带码表,不依赖任何外部信息:

```
偏移 0   : 1 字节  magic 0x48
偏移 1   : 2 字节  出现的字节值种类数 n(1..256,小端)
偏移 3   : 8 字节  原始数据长度(小端)
偏移 11  : n × {1 字节 字节值, 1 字节 该字节值的码长}
之后      : 比特流,高位在前,末字节不足 8 位补 0
```

* 码表只存**码长**,实际码字按哈夫曼规范码规则(按码长升序、同长按字节值升序依次分配)重建,所以编码端和解码端用同一套规则推导码字,不必传码串;
* 解码端能重建码表的前提是码长集合是一个完备前缀码,`decode` 会校验并拒绝非法码表(码长为 0、符号重复、过订阅、不完备);
* 头部记录了原始长度,所以末字节的补零位不会解出多余字符,也不需要在归档里另存长度。

## 元数据

* 解包时会写回文件的权限、访问/修改时间,**目录的修改时间会在所有子项解出后统一恢复**,与 tar 的做法一致;
* 属主(uid/gid)也会尝试恢复,但只有具备相应权限(通常需要 root)时才会真正生效;
* ctime 由内核维护、不可手动设置,不参与恢复。

## 安全与说明

* 解包时会拒绝包含 `../` 或以 `/` 开头的路径,防止路径穿越;
* 也会拒绝头部里没有 `\0` 结尾的路径,以及声明长度超过剩余数据的记录,避免越界读写;
* 非哈夫曼格式的文件、码表非法或数据被截断/损坏的归档都会报错退出,不会静默写出残缺文件;
* 打包需要把整个归档读进内存(原始数据 + 压缩结果各一份),超大归档请注意内存占用;
* 已知限制:路径长度上限 4096 字节;单文件打包时归档内的路径是该文件的基本名(basename);符号链接会按其目标打包成普通文件;时间戳只精确到秒。
